# 実況側との検出基準（2026-09-23）

## 合意した仕様

- ソロプレイを前提とする。
- プレイヤーから水平距離15m以内（XZ、高低差無視）の生存ゾンビを対象とする。
- この範囲内にプレイヤーを攻撃対象とする生存ゾンビが1体以上いれば実況上の戦闘中と判定する。攻撃命中・視認・到達可能性を意味しない。
- 生存ゾンビを検出したが敵対対象がない場合は「敵がいるっぽい」程度の気配として扱う。
- 正常走査で0体と、読取失敗・途中終了を区別する。範囲内0体から全域の安全や全滅を推論しない。
- 敵種別の分類改訂はレーダーとTelemetryで整合させる。
- 実況はまず話題候補を増やし、その後で文脈・新規性・緊急性・既発言との重複により優先順位を調整する。持ち替えを一律除外しない。

## ソースで確認した現状

RadarRuntime.ScanはEntityAlive.IsDead()で死亡個体を除外し、XZ距離で範囲を判定する。512件の打ち切りはない。IsZombieは継承元を含む型名のZombie判定。ModApiはOnEntityDeathへのHarmony postfixから死亡表示を記録する。レーダーには攻撃対象判定はまだない。

TelemetryのNearbySummaryは現状3D距離で、死亡除外・走査完了情報がなく、512件で打ち切る。これを上記仕様に合わせる改修は未実装。

## 次の改修範囲

1. Telemetryで明示的な生存判定、水平15m内の生存数・プレイヤー狙い数・最短水平距離を取得する。既存3D項目の意味を無断で変更せず別項目にする。
2. 走査完了・読取失敗・不明な攻撃対象を識別し、失敗を0として扱わない。
3. AITuberで戦闘・気配の状況を候補化し、行動や資源変化と結び付ける。
4. レーダーとTelemetryの敵分類を改訂する際は同じ定義と事例で照合する。
